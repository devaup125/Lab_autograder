    Problem Statement

    Given an integer array nums and an integer target, return the indices of the two numbers such that they add up to the target.

    You may assume that each input has exactly one solution, and you may not use the same element twice.

    Return the answer in any order.

    Objective

    Design an efficient algorithm with optimal time complexity to find the required pair of indices.

    Input Format
    • First line contains integer n
    • Second line contains n integers
    • Third line contains integer target
    Example 
    4
2 7 11 15
9
    Output Format

    Print the indices of the two numbers whose sum equals the target.

    Example 
    0 1
    Constraints
    • 2 ≤ n ≤ 100000
    • -10⁹ ≤ nums[i] ≤ 10⁹
    • Exactly one valid answer exists.
    • Target fits in 32-bit integer
    • Expected Complexity: O(n)
    • Extra Space: O(n)
    Important Notes
    • Exactly one solution is guaranteed.
    • Do not use the same element twice.
    • Output order does not matter.
    • Try to achieve O(n) complexity.
    Additional Example
    Input 
    3
3 2 4
6
    Output 
    1 2

    Explanation: The values 2 and 4 add up to 6.

    Detailed Explanation

    A brute-force solution checks every possible pair of elements. Although simple, it requires O(n²) time.

    A better solution uses a Hash Map. Store each element while traversing the array. For every number, calculate target − current_number. If that value already exists in the hash map, return both indices immediately.

    Optimal Complexity
    • Time Complexity: O(n)
    • Space Complexity: O(n)
    Hints
    1. Can you solve this without checking every pair?
    2. What data structure supports O(1) lookup?
    3. Store previously visited numbers.
    4. Search for target - current value.
    5. Return indices immediately after finding a match.
    Complexity Analysis
    Approach Time Space
    Brute Force O(n²) O(1)
    Hash Map O(n) O(n)
